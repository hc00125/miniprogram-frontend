# 排行榜接口对接草案

当前前端支持老板贡献榜、陪玩接单榜的日榜、周榜、月榜。后端接口尚未提供。未配置时显示“榜单暂未开放”，不会请求虚构地址，不用历史订单总数冒充时间榜单，不展示示例人物或假排名。

## 已确认与待确认口径

- 用户已确认老板贡献为消费钻石合计：点单 + 礼物 + 冠名。充值和余额不是消费，不计入。
- 建议按已支付消费扣除退款/冲正计算；退款归属原消费期还是退款期，需后端与业务确认。
- 陪玩按接单量统计；具体按接单成功时间、是否扣除取消订单、跨期订单归属需业务确认。
- 建议用北京时间自然日、周一至周日自然周、自然月。起点包含、终点不包含，最终时间边界由后端返回；前端不自行汇总。
- 建议同值并列，下一名跳位，例如 1、1、3。仅返回允许公开的昵称和头像，不返回手机号、openid、个人余额等。

## 显式启用

后端确认并实现此协议后，再在本地/部署构建环境配置 `VITE_RANKINGS_API_PATH=/rankings/` 并重新构建。此地址是提议，不表示服务器已有该接口。仅接受相对 API 路径，拼接既有 `BASE_URL`，不接受外部主机、查询字符串或路径跳转。当前不设置该变量。

GET 参数 `board=boss|player&period=day|week|month`。只读公开榜单，不发送用户 token。HTTP 200，以下两种响应二选一：

```json
{ "available": false }
```

已开放响应字段：

| 字段 | 类型与规则 |
| --- | --- |
| available | `true` |
| board / period | 与请求相同 |
| period_start / period_end | 带时区 ISO 8601 时间；结束晚于开始，区间左闭右开 |
| updated_at | 带时区 ISO 8601 更新时间 |
| results | 最多 50 行，空数组表示本期无人上榜 |
| results[].id | 唯一非空字符串，公开行标识 |
| results[].rank | 正整数、升序，可同名次 |
| results[].name | 非空公开昵称 |
| results[].avatar_url | 可选 HTTPS 或服务器相对路径；缺失/加载失败显示昵称首字 |
| results[].value | 非负数、降序；老板为钻石数，最多 1 位小数且换算为十分之一钻石后须为安全整数（沿用 `normalizeDiamonds`）；陪玩为非负安全整数，单位单 |

接口错误、字段异常、统计范围不匹配显示可重试错误态，不假装“没有数据”。切换榜别/周期或离开页面后，旧请求结果不再更新当前画面。

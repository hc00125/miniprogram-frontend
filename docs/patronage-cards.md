# 冠名卡片

首页推荐与大神列表沿用真实陪玩、评分和冠名接口数据。

- 有效冠名显示头像冠冕、金色头像圈、卡片金边、金色铭牌和冠名按钮；没有有效冠名时使用普通卡片。
- 铭牌显示老板头像、完整昵称和套餐，连同“感谢 ×× 老板冠名 · 年冠，谢谢老板的支持，祝老板玩得开心！”等长句，从右向左连续滚动。单老板同样滚动，多老板按接口顺序接续，重复的一组消息负责无缝循环；铭牌高度固定，点击在当前位置暂停或继续。完整内容保留在无障碍标签中，详情页仍显示完整多人名单和到期时间。
- 首页推荐卡把在线状态和评分移到昵称、分类右侧，保持两列和原有推荐顺序；暂无评价时显示未评分。
- 大神页的冠名、送礼和服务入口同排展示。搜索、分类、收礼人、冠名对象及服务可用条件保留原有行为。
- 加载、失败、换陪玩或隐藏页面时清除旧冠名装饰；迟到的旧响应不能重新给其他陪玩添加冠冕。

冠名不独占、不锁单。多人显示沿用接口顺序，不增加冠名金额排名、VIP 等级或额外权益。随机陪玩与优质陪玩选项仍仅切换界面状态，具体规则继续由维护者接入。

`PatronageCrowns` 的 `active-change` 事件只表示当前陪玩是否有有效冠名，父页面用它管理装饰。铭牌配色复用各主题的 gold / gold-soft / gold-line。`GiftHost` 的可选 `--gift-entry-compact-min-height` 变量只调整入口高度，原礼物权限和支付逻辑保持不变。

紧凑铭牌使用明确左右边界及高度的普通 view 裁切横向轨道，CSS linear translateX 动画连续移动两组相同消息，播放时长随文案长度调整。冠冕与暂停图标固定在两侧，文字保留一行且不省略。暂停使用 animation-play-state，不重新启动到起点。文案列表及冠名榜单投影使用普通循环，避免依赖部分运行环境缺少的 Array.flatMap；回归检查覆盖此方法不存在时的实际数据渲染。

构建后，在微信开发者工具点击“编译”，检查首页推荐和大神页。检查单人和多人感谢词连续横向滚动、点击暂停/继续，以及长昵称和套餐显示。实际滚动速度、循环衔接和字体效果需在模拟器或设备确认。

## 冠名榜单

排行榜按“冠名榜单、老板贡献榜、陪玩接单榜”排列，默认在本页直接显示冠名榜单。冠名页签不显示日周月，也不发起统计榜请求；两个统计页签继续使用原有日、周、月接口。冠名通报标题右侧入口仍打开普通页面 `pages/client/patronage-wall/index`。两个位置复用 `PatronageWallPanel`，集中展示当前有效冠名的公开陪玩、每条老板昵称和套餐，保持真实陪玩列表顺序，不额外生成名次或金额排序。

“查看服务”进入既有陪玩详情并传该卡片的真实 `playerId`；该页继续处理休息、不可指定、已离开和商品可用状态。“冠名/包天”进入同一陪玩的既有套餐页。历史通报仍保留原类型和分页。

数据层 `src/api/patronageWall.ts` 优先请求 `GET /api/patronage/wall/`，新后端通过一次 GET 返回全部当前有效冠名的公开陪玩及老板套餐。完整未分页合同为 `{ contract_version: '1.0', count, results: [{ player: { id, name, avatar_url, type_name }, crowns }] }`，`count` 与陪玩条目数一致，冠名仍沿用既有七个公开字段。有效期在客户端再次过滤；只有成功取得完整结果后才显示“当前”或真实空榜。

只有汇总请求返回 HTTP 404 才兼容旧后端，继续读取未筛选的公开陪玩全集并调用既有单人冠名接口。全模块最多 8 个并发冠名请求，包括刷新时尚未结束的旧请求。每位查询完成立即发布当前真实有效冠名，未完成时显示“已找到”和进度；查完才显示“当前”。查询失败保留已查到的卡片并提示部分加载失败；没有卡片时显示失败与重试，均不当作空榜。汇总接口的其他 HTTP 错误、网络错误或异常合同直接显示失败，不再发起旧扫描。隐藏后停止为无消费者的扫描安排新请求，旧响应不能回填页面。

同会话的两个入口共享正在进行的汇总读取或兼容扫描，完整成功结果在内存缓存 60 秒；缓存命中、部分更新及查询完成均重新过滤有效期，并复制数据避免页面修改共享结果。未完成或失败结果不缓存。手动刷新绕过缓存并重新请求汇总，登录令牌或会话代次改变时隔离缓存，购买页仅在原单 GET 确认已支付后撤销缓存。加载器只有 GET，不参与扣款。

新汇总接口部署后，首次未缓存的完整加载只需 1 次 GET。旧后端兼容读取则需要 1 次汇总探测、1 次公开列表和 N 次单人冠名，即 N + 2 次 GET；例如 N = 142 时为 144 次。旧公开列表目前按未分页数组读取，没有冠名标记，单人冠名接口要求 `player_id`；如旧列表改为分页，应同步更新全集读取，现有代码会报错而非悄悄漏人。冠名通报属于历史记录，不能代替当前冠名数据。

本轮后端源码及离线读取回归已完成，尚未部署新接口，也未测量生产耗时。一次 GET 的路径已接入前端，但只有服务器实际提供汇总合同后才会使用；不能把源码与离线测试通过描述为线上已提速。

手动验收：排行榜默认冠名且三个页签顺序正确，通报入口打开相同名单；新接口部署后确认首次加载使用单次汇总 GET，旧服务器 404 时确认逐步出现真实卡片。检查再次进入、强制刷新和失败保留部分卡片的状态；非 404 失败不得悄悄改走旧扫描。检查实际冠名人名、套餐、头像和单人/多人滚动与暂停；选择另一位陪玩核对“查看服务”及“冠名/包天”目标。旧服务器的首次完整扫描仍可能较慢；本轮没有批量请求生产数据或测量真实耗时。

## 我的页面 VIP 卡片

原账号信息页的 VIP 头衔、成长钻石、等级进度、权益标签和“累计钻石记录”整块移到“我的”页，在可用钻石余额卡片下方。仅已登录且取得个人资料后显示，复用个人页已有资料刷新，不新增 VIP 请求。

`VipSummaryCard` 沿用原 `ClientProfile.vip` 数据、全部等级配色及累计成长钻石后备值；成长钻石与钱包可用余额分别使用原字段。累计钻石记录仍进入既有 `pages/client/growth-records/index`。账号信息页继续保留头像、昵称、钱包和专属 KOOK 房间配置详情。

手动验收：“我的”页钱包下方显示真实头衔、成长值及权益；点击累计钻石记录能打开原记录页；点头像进入账号页核对资料编辑及 KOOK 房间。未登录时不显示 VIP 卡片。

## 修改布局后完整编译

本地开发者工具曾开启 `project.private.config.json` 的 `setting.compileHotReLoad`。本次关闭该项目的编译热重载，并保留原配置备份；本地私有配置不提交，登录缓存没有清除。修改 uni-app 模板结构会改变生成 WXML 和 JS 的数据键，更新模板时继续使用旧页面实例，会把图标路径或布尔值显示成文字，也会使嵌套冠名消息为空。

隔离编译前一提交后，使用旧 JS 与新 WXML 复现“抢单大厅”副文字变成 `/icons/themes/mist/reviews.png`、旁边标题变成 `false`，以及冠名条只剩两侧图标；匹配版本的编译产物读出正确文字和消息。此复现解释了使用者截图中的异常，尚未直接读取其运行窗口确认实际缓存状态。

重新构建后，先退出当前项目回到开发者工具项目列表，再重新打开当前项目，在“清缓存”下拉选择“清除编译缓存”，然后点“编译”，重新进入“我的”和大神页。这样重建页面实例；仅页面刷新或热重载可能保留旧 JS。已从本地开发者工具安装代码核对，“清除编译缓存”与数据缓存、登录状态的清理是不同动作。其他维护者可在本地私有配置设置 `"compileHotReLoad": false`。

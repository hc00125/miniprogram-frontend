# 冠名卡片

首页推荐与大神列表沿用真实陪玩、评分和冠名接口数据。

- 有效冠名显示头像冠冕、金色头像圈、卡片金边、金色铭牌和冠名按钮；没有有效冠名时使用普通卡片。
- 铭牌显示老板头像、昵称和套餐。每位老板轮替“感谢 ×× 老板”和“×× 冠名支持”，每 3.6 秒纵向切换，单老板也轮播；铭牌高度固定，点击铭牌暂停或继续。完整老板昵称、套餐及感谢文字保留在无障碍标签中，详情页仍显示完整多人名单和到期时间。
- 首页推荐卡把在线状态和评分移到昵称、分类右侧，保持两列和原有推荐顺序；暂无评价时显示未评分。
- 大神页的冠名、送礼和服务入口同排展示。搜索、分类、收礼人、冠名对象及服务可用条件保留原有行为。
- 加载、失败、换陪玩或隐藏页面时清除旧冠名装饰；迟到的旧响应不能重新给其他陪玩添加冠冕。

冠名不独占、不锁单。多人显示沿用接口顺序，不增加冠名金额排名、VIP 等级或额外权益。随机陪玩与优质陪玩选项仍仅切换界面状态，具体规则继续由维护者接入。

`PatronageCrowns` 的 `active-change` 事件只表示当前陪玩是否有有效冠名，父页面用它管理装饰。铭牌配色复用各主题的 gold / gold-soft / gold-line。`GiftHost` 的可选 `--gift-entry-compact-min-height` 变量只调整入口高度，原礼物权限和支付逻辑保持不变。

构建后，在微信开发者工具点击“编译”，检查首页推荐和大神页。检查单人和多人感谢词切换、点击暂停/继续，以及长昵称和套餐显示。实际显示、原生轮播和字体效果需在模拟器或设备确认。

## 冠名榜单

排行榜的第三个按钮与冠名通报标题右侧入口均打开普通页面 `pages/client/patronage-wall/index`。页面集中展示当前有效冠名的公开陪玩、每条老板昵称和套餐，保持真实陪玩列表顺序，不额外生成名次或金额排序。

“查看服务”进入既有陪玩详情并传该卡片的真实 `playerId`；该页继续处理休息、不可指定、已离开和商品可用状态。“冠名/包天”进入同一陪玩的既有套餐页。历史通报仍保留原类型和分页。

数据层 `src/api/patronageWall.ts` 使用未筛选的公开陪玩全集，最多 4 个并发调用既有单人冠名接口；等待完整查询成功后显示有效冠名。任一查询失败显示重试状态，不把缺失数据当空榜；隐藏页面后停止安排新请求，旧响应不能回填页面。数据均来自 GET 请求，没有购买写入。

当前后端公开陪玩列表是未分页数组，冠名接口要求 `player_id`，尚无全体有效冠名接口。完整加载为 1 + N 次 GET；当前 142 位公开陪玩对应 143 次请求。朋友可后续提供一次返回全部当前冠名陪玩和各老板套餐的公开汇总接口，再替换此数据层；如列表改为分页，应同步更新全集读取，现有代码会报错而非悄悄漏人。冠名通报属于历史记录，不能代替当前冠名数据。

手动验收：两个入口能打开同一页面；检查实际冠名人名及套餐、头像、刷新、单人/多人轮播与暂停；选择另一位陪玩核对“查看服务”及“冠名/包天”目标。首次全体核验可能比普通榜单慢，加载与错误状态需一并检查。
